# 桌面端演示与答辩脚本（10 分钟版）

> 适用对象：答辩现场演示者。所有步骤均在图形界面上完成，右侧「SQL 预览」面板同步显示
> 数据库真实收到的语句，供答辩对质。

## 一、演示前准备（2 分钟）

```bash
# 1) 确认 3307 演示库在线（/tmp 被清理后需要重建，见 .agent/state.md）
mysqladmin --protocol=tcp -h127.0.0.1 -P3307 -uroot status

# 2) 还原演示数据（幂等，重建库并载入模拟数据集）
cd ../学生选课与成绩管理系统 && bash scripts/init_db.sh -u root -P 3307

# 3) 启动桌面端
cd ../edu_desktop && bash run.sh
```

登录窗口使用 `admin / Admin@123`；若要演示角色裁剪，可在工具栏「角色」下拉里切换。

## 四、常见提问与回答

| 提问 | 回答要点 |
| --- | --- |
| 图形界面和提交的控制台版是两套程序吗？ | 同一套数据库、同一批视图与存储过程；Java 版是提交物，Qt 版是演示层，只在界面层不同。 |
| 界面会不会绕过 SQL 直接改数据？ | 所有写操作都经 `db/dao` 的参数化 SQL 或存储过程；SQL 预览面板可逐条核对。 |
| 为什么界面没有全部用 ORM？ | 课程要求手写 SQL，且红线 §11(3) 禁止 ORM；这里用 PyMySQL + 参数化语句。 |
| 选课并发安全吗？ | 由 `p_enroll_student` 内的 `SELECT ... FOR UPDATE` 行锁与触发器共同保证，控制台版有并发测试用例。 |
| 审计日志的操作者为什么是 root？ | 触发器按 DEFINER 执行，`CURRENT_USER()` 返回定义者；这是 MySQL 存储程序的安全上下文。 |
| 权限页为什么看不到例程级授权？ | MySQL 8.4 未在 `information_schema` 暴露该视图，`mysql.procs_priv` 对应用账号不可读（实测 1142）；改以模式级授权 + 越权实测佐证。 |
